# Talk with Jesus — Cloudflare Worker

A mobile-friendly, church-inspired AI reflection website powered by Groq. It includes automatic model fallback, a gentle message reveal effect, optional ambient organ-like audio generated in the browser, and browser text-to-speech.

## Files
- `public/index.html` — website UI and browser interactions
- `src-worker.js` — `/api/chat` endpoint, model fallback, server-side Groq key usage
- `wrangler.toml` — Cloudflare Worker and static asset configuration

## Deploy
1. Create/choose a Cloudflare Worker project connected to this repository.
2. In Worker Settings → Variables and Secrets, add `GROQ_API_KEY` as a **Secret**.
3. Keep `GROQ_MODEL` set to `openai/gpt-oss-120b` or omit it to use that default.
4. Deploy with `npx wrangler deploy`.

Never put `GROQ_API_KEY` in `public/index.html` or commit it to GitHub.

## Model fallback
The Worker tries, in order: `openai/gpt-oss-120b`, `qwen/qwen3.8-27b`, and `openai/gpt-oss-20b`. On HTTP 429 it uses `Retry-After` / rate-limit reset headers when present and temporarily cools down that model. It retries the next available model and returns to the primary when its cooldown expires. Cooldowns are an in-memory, best-effort cache per Worker isolate; they are not globally persistent, so occasional repeated attempts can happen after an isolate restart. Provider-wide exhaustion still means all models may be unavailable.

## Audio
Ambient audio is generated locally in the browser with Web Audio (no audio file or third-party audio API required). Browser speech synthesis uses voices installed on the visitor's device and may sound different across devices. Audio is opt-in and starts only after a user gesture.

## Important
The donation dialog is a non-payment prototype; no payment is collected. The AI character is clearly presented as AI and must not promise blessings, miracles, healing, or financial returns in exchange for donations.


## Cost and abuse protections in this version

- User message maximum: 1,200 characters (validated in the browser and Worker).
- Request body maximum: 32 KB.
- Conversation history: up to 6 recent messages, each truncated to 900 characters.
- Model output: capped at 130 completion tokens, with a short-answer system instruction.
- Best-effort rate limit: 10 messages per IP per minute per Worker isolate. This is not a global or tamper-proof limit because isolate memory can reset or differ between isolates. Before public launch/payment, configure Cloudflare's rate limiting or a Durable Object-backed limiter.
- Model can be selected in the chat UI; the Worker validates the requested model against the allowlist and can fall back when a model is unavailable.
- Ambient sounds are generated locally by the browser after the user presses Play; no external audio file is loaded. Browser/device audio support and mute settings can affect playback.


## Front-end structure
- `public/index.html`: page structure and content.
- `public/css/style.css`: styles, responsive layout, and animations.
- `public/js/app.js`: chat, speech synthesis, ambient sound, and donation prototype interactions.
- `src-worker.js`: server-side chat endpoint and model fallback.

Model selection and provider labels are not exposed in the interface; server-side fallback remains enabled. The footer retains a plain-language disclosure that conversations are generated by software and may be inaccurate.


## Crypto Pay donations

Add `CRYPTOPAY_API_TOKEN` as a **Worker Secret** in Cloudflare (Production environment), then deploy. The site creates fixed USD-denominated voluntary-support invoices for $1, $5, $10, or $25 using the Crypto Pay API and checks invoice status server-side through `getInvoices`. The API token must never be exposed in browser code or committed to Git.

Payment endpoints: `POST /api/create-invoice` and `GET /api/payment-status?invoice_id=...`. This initial integration uses status polling rather than webhooks. Test using Crypto Pay's test environment and test token before enabling real payments; mainnet invoices can accept real funds. Check Crypto Pay's current terms and eligibility rules for your account and country before accepting real payments. This is voluntary support, not a purchase of spiritual services.


## Crypto Pay web invoice
The create-invoice endpoint prefers `web_app_invoice_url` when Crypto Pay returns it, and falls back to `pay_url` if it does not. The hosted payment page opens separately; Crypto Pay controls that page and may not permit embedding it inside the website. Payment status is verified server-side with `getInvoices`.


## NOWPayments direct payment + Neon setup

Required Cloudflare Worker secrets: `GROQ_API_KEY`, `DATABASE_URL` (Neon pooled connection string), `NOWPAYMENTS_API_KEY`, and `NOWPAYMENTS_IPN_SECRET`. Never commit secret values. The Worker creates the `payments` table automatically on the first payment request.

This version uses the NOWPayments **Payment API** directly for `usdttrc20` rather than opening the hosted invoice currency picker. It displays the exact amount and destination address returned by NOWPayments. The visitor must send only USDT on the TRON/TRC20 network to that exact address. If the API says the currency is unavailable or rejects the request, the site shows the provider's safe error message; code cannot override account or provider-side currency restrictions.

Configure the NOWPayments IPN callback URL to `https://YOUR-WORKER-DOMAIN/api/nowpayments-ipn`. The IPN secret must match `NOWPAYMENTS_IPN_SECRET`. Only the NOWPayments `finished` status is shown to the visitor as paid. Verify the deployed worker and run a small permitted test before accepting real donations. Check provider terms, account eligibility and local requirements before accepting payments. Support is voluntary and is not a purchase of spiritual services.


Donation amounts in the current UI are $25, $30, $50, and $100, plus a custom USD amount. Both the browser and Worker enforce a minimum of $25; custom amounts can be entered with up to two decimal places.
